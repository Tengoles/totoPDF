# Spanish Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every string a user can read in ordinary use is available in Spanish, selected automatically from Chrome's UI language.

**Architecture:** Chrome's native `chrome.i18n`, with catalogues authored in `src/i18n/<locale>.json` and copied to `dist/_locales/<locale>/messages.json` at build time. A thin `t()` wrapper in `src/core/i18n.ts` types message keys as a union derived from the English catalogue, so a missing key is a typecheck failure rather than a blank control; outside the extension (vitest's node environment) it falls back to reading the English catalogue directly, so existing tests need no `chrome` mock.

**Tech Stack:** TypeScript 5.9, Vite 7, vitest 3, Playwright 1.62, `chrome.i18n` (MV3).

**Spec:** `docs/superpowers/specs/2026-08-13-i18n-design.md`

## Global Constraints

- **The English catalogue reproduces today's copy verbatim.** Byte for byte, including the double space in `p.$PAGE$  $TEXT$` and the missing trailing period in `Could not load … (HTTP …)`. Existing unit and e2e specs assert this copy as literals; changing it silently breaks them. Copy improvements are a separate decision, not part of this work.
- **Exactly one existing assertion changes**, in `test/unit/settings.test.ts` (Task 4, Step 3). Every other existing spec must pass untouched. Editing any other spec to accommodate `t()` means the fallback path is wrong — fix the fallback, not the spec.
- **Locale code is `es`, not `es_419`.** Chrome's fallback is `es_419` → `es` → `default_locale`, so a catalogue at `es_419` alone serves English to a plain "Español" Chrome.
- **Spanish register is Latin American tuteo.** Not voseo, not `usted`.
- Files under 300 lines. Functions under 50 lines. No `any`.
- Placeholder keys in `messages.json` are lowercase; the `$NAME$` reference in the message text is uppercase.
- Palette display names must match `^[A-Za-z0-9 _-]+$` and contain no `,` or `=` — they are serialized into pdf.js's colour-string parser.
- The word "Highlight" (English) and "Resaltar" (Spanish) must not appear in a swatch's `title`. The e2e specs locate the Highlight button by accessible name and Playwright matches by substring.
- `default_locale` in the manifest without `_locales/` in `dist/` makes Chrome refuse to load the extension outright. The build change and the manifest change land in the same commit.

- [ ] **Step 4: Write the module**

Create `src/core/i18n.ts`.

```ts
import en from '../i18n/en.json';

/**
 * Every key in the English catalogue, as a union. chrome.i18n.getMessage
 * returns the empty string for a key it does not know and reports it only to
 * the console -- a silently blank button. Typing the key against the
 * catalogue makes that unwritable rather than merely unlikely.
 */
export type MessageKey = keyof typeof en;

interface MessageEntry {
  message: string;
  placeholders?: Record<string, { content: string }>;
}

const CATALOGUE: Record<string, MessageEntry> = en;

/**
 * chrome.i18n's own substitution, reimplemented for the node test environment.
 * Passing a function to replace() is what keeps a '$1' inside a substituted
 * value -- an excerpt from a PDF, say -- from being expanded a second time.
 */
function substitute(entry: MessageEntry, subs: readonly string[]): string {
  const placeholders = entry.placeholders ?? {};
  return entry.message.replace(/\$([A-Za-z0-9_]+)\$/g, (whole, name: string) => {
    const content = placeholders[name.toLowerCase()]?.content;
    if (content === undefined) {
      return whole;
    }
    return subs[Number(content.slice(1)) - 1] ?? '';
  });
}

/** Undefined under vitest, which runs in node with no extension APIs. */
function i18nApi(): typeof chrome.i18n | undefined {
  return (globalThis as { chrome?: typeof chrome }).chrome?.i18n;
}

/**
 * The one way any string reaches a user. Outside the extension it reads the
 * bundled English catalogue directly, which is what lets the unit specs go on
 * asserting real copy with no chrome mock.
 */
export function t(key: MessageKey, ...subs: string[]): string {
  const api = i18nApi();
  if (api) {
    return api.getMessage(key, subs);
  }
  const entry = CATALOGUE[key];
  // Unreachable: MessageKey is derived from CATALOGUE's own keys.
  return entry ? substitute(entry, subs) : key;
}
```

const LOCALES = ['en'];

function copyStaticAssets(): Plugin {
  return {
    name: 'copy-static-assets',
    apply: 'build',
    async closeBundle() {
      await cp(resolve(PDFJS_ROOT, 'build/pdf.worker.mjs'), resolve(OUT, 'pdf.worker.mjs'));
      for (const dir of ['cmaps', 'standard_fonts', 'wasm']) {
        await cp(resolve(PDFJS_ROOT, dir), resolve(OUT, dir), { recursive: true });
      }
      // Chrome refuses to load an extension whose manifest names a
      // default_locale with no _locales directory beside it, so this is not
      // optional once the manifest change above has landed.
      for (const locale of LOCALES) {
        const target = resolve(OUT, `_locales/${locale}`);
        await mkdir(target, { recursive: true });
        await cp(
          resolve(import.meta.dirname, `src/i18n/${locale}.json`),
          resolve(target, 'messages.json'),
        );
      }
    },
  };
}

const PALETTE_NAME_KEYS: Record<string, MessageKey> = {
